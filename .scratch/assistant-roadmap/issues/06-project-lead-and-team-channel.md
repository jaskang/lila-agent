# 06：项目主理人（Project Lead）与受控团队群聊（Team Channel）

Status: needs-triage

## 背景与目标

解决多窗口/多端会话上下文割裂、需要人工搬运 `sessionId` 的痛点：让每个项目拥有一个永恒在线的主频道（Team Channel），用户只需在一个入口交流，由 **Project Lead** 掌握全局进度并调度角色化 Sub-Agent（工程师、视觉验收/设计还原、代码审查员等），同时在顶部展示团队成员实时工作状态。

## 核心架构原则（防上下文爆炸 & 防多 Bot 演戏空转）

1. **交互主时间线与 LLM 上下文窗口彻底解耦（5 层省 Token 架构）**：
   - **主 Bot 只指挥不下场**：重体力活（读大量文件、跑构建测试、看设计稿）全部下放到短命 Sub-Agent 独立上下文（配 Git Worktree + `workspace-write` OS 沙箱），结束后只向 Lead 回传 300–500 Token 结构化战报（结论 / 改动文件 / 验证结果 / 风险 / `sessionId` 指针）。
   - **外置项目活态总账（Project Ledger）**：按项目维护严格控长（`<= 2,000 tokens`）的结构化总账（仓库近况、活跃 Worktree、进行中/刚完成的任务与 Sub-Agent 摘要、关键约定），代替用超长对话历史硬记。
   - **滚动窗口 + 按需历史召回**：主频道 UI 可无限上滑，喂给 LLM 的消息仅保留活跃窗口；旧对话走 Guided Compaction 沉淀到 Ledger/`MEMORY.md`，完整原文留存在本地 JSONL，通过 `project_history_search` / `session_read` 工具按需检索（平时 0 Token）。
   - **跨会话自动回流**：专项会话、定时任务或其他客户端会话结束时，用轻量模型自动生成 3 行摘要事件写入该项目 Ledger，彻底消灭手动传递 `sessionId`。
   - **模型分层与缓存前缀稳定**：Lead 使用高性价比快模型并保持前缀稳定以吃满 Prompt Cache；重型编码/疑难排查按需路由给旗舰模型。
2. **受控团队群聊（Slack 频道 + 线程模型，禁止 Bot 自由互聊）**：
   - **主群聊只放高信噪比里程碑**：你的消息、Lead 回复与派单、各角色完成后的结构化交付卡片、审批/澄清卡；中间数十步工具调用全部折叠在各自专属线程（点击右侧展开 `SubsessionPreview`）。
   - **严格 Hub-and-Spoke 发言权**：普通消息默认仅由 **Lead** 响应；其他角色仅在被 Lead 派活或被用户显式 `@角色` 点名时工作并汇报，禁止 Bot 之间在群里互相客套刷屏。
   - **克制的核心角色（3–4 个，复用 `pi-subagents` `.pi/agents/*.md`）**：
     - `@lead`（项目主理人）：管总账、拆解需求、派活、管收件箱与定时任务；
     - `@builder`（工程师）：配 Worktree + OS 沙箱，专注编码与验证；
     - `@qa` / `@designer`（设计还原与视觉验收）：专攻公开 HTML 交互设计稿探索与双页同视口对拍；
     - `@reviewer`（审查员）：严格只读权限，独立审 Diff 与 Spec 漏项。

## 分阶段落地建议

- **阶段 A（先立骨，不动大 UI）**：
  1. 定义项目级 `Project Ledger` 存储与自动回流钩子（会话/定时/任务完成时更新摘要）；
  2. 提供 `project_history_search` 跨会话只读检索工具；
  3. 基于 `pi-subagents` Custom Agents 预置 `builder / qa / reviewer` 最小角色模板（各自绑定最小工具集与模型档位）；
  4. 每个项目支持指定或置顶一个默认 Lead 主会话。
- **阶段 B（再塑形，升级群聊体验）**：
  1. 侧栏为每个项目置顶「项目主群」，保留可选专项会话（结束后自动回流总账）；
  2. 对话区顶部增加轻量「团队成员状态条」（头像/角色 + 运行/等待/待命状态，点击在右侧展开工作线程与 Diff，支持 Stop/Steer）；
  3. 输入框 `@` 补全支持 `@builder` / `@qa` / `@reviewer` 直达路由，主群聊气泡区分角色徽标与结构化交付卡片。
