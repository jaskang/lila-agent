# Lila 开发计划

2026-11-13 定。架构见 `architecture.md`。这份文档取代 `product-v3/v4.md` 里的路线图。

目标的顺序：先让 Lila 成为你每天用的个人助手（编程，加上邮件和日历、待办跟进、调研和写文档、定时简报），用下来稳了再考虑给别人用。

## 现在在哪

分支 `omp-harness`（从 `main` 切出），改动都还没提交。

| 已完成 | 结果 |
|---|---|
| 精简成只用 omp | 删掉 Claude Code、Codex 两个引擎和终端、hook、账号用量等，约 2.8 万行 |
| omp 接入换成 RPC | 流式对话、工具卡片、权限卡片、提问卡片、会话续聊、模型菜单 |

验证到的程度：测试和 clippy 全过；真 omp 加 magpie 跑过普通回复、出权限卡片并允许执行、停止后续聊。**没有验证**：窗口接真后台用鼠标点、agent 真的提一个问题、改文件和 MCP 工具的权限卡片。

## 阶段

每个阶段做完的标志是「你能用它做到某件事」，不是代码写完。

### P1 一个程序

把后台的 lilad 并进窗口程序，去掉 herdr-core。

- 服务核心改成库，窗口启动时在自己进程里跑；omp 作为它的子进程。
- 关窗口不退出，留在后台；再次打开回到原来的状态。
- socket 保留给命令行；删掉版本握手、重启 lilad 的提示和按钮。
- crate 按 `architecture.md` §4 整理，`hc-client` 删除。

**完成标志**：只装一个程序、只依赖 `omp`，就能开会话干活；关掉窗口后会话还在跑，重新打开能看到结果。

### P2 能每天用

把现在知道的毛病修掉，然后开始自用。之后的阶段都在 Lila 里做。

- Lila 自己的 omp 配置目录（`architecture.md` §6）。
- 原生系统通知：会话在等你、一轮跑完时通知，点击跳到那个会话。
- 拒绝时可以写理由，作为附言发给 agent。
- 提问卡片：密码类输入打码；侧栏和通知对提问写「要你回答」。
- 删除会话时清掉它的 omp 会话目录；清理库里旧引擎留下的东西。
- 把「没有验证」的那几项用真 omp 和真鼠标走一遍，修掉发现的问题。

**完成标志**：你用 Lila 做完一天的编程工作，没有因为它的毛病回到终端。

### P3 看得见它在干什么

- 子 agent：显示每个子 agent 的任务和状态，可展开看它的对话。
- 待办和计划：显示 agent 当前的清单。
- 上下文占用：显示用了多少，快满时提示。
- 会话标题自动生成；长对话往前翻页。
- 代码块语法高亮。

**完成标志**：一个跑了半小时的会话，你扫一眼就知道它做到哪了、卡在哪。

### P4 邮件、日历和待办

- 在设置里按工作区开关集成；实现上是往 Lila 的 omp 配置里写 MCP server。
- 接入邮件和日历（用哪家的服务待定，见待定事项 2）、Asana。
- GitHub 不接 MCP，agent 直接用 `gh`。
- 对外发出的动作（发邮件、建日程、发评论）即使在全自动档也出卡片。

**完成标志**：你说「看一下今天的邮件，把需要我回的列出来，起草回复」，它做到，发出前等你点头。

### P5 定时任务和简报

- 定时任务：一句话加一个时间规则，到点在指定工作区开一个会话跑。
- 跑完发通知，结果是一个普通会话，可以接着聊。
- 登录时自动启动，这样不开窗口也会触发。
- 定时会话没有人在旁边看，所以对外发出的动作一律等你点头，不管会话是哪一档。

**完成标志**：每个工作日早上 9 点，你收到一条通知，点开是今天的日程、要回的邮件和 Asana 上到期的事。

### P6 调研和写文档

- 浏览器或搜索能力（选现成的 MCP server）。
- 调研结果写成工作区里的文档；长任务用子 agent 分头查。

**完成标志**：你给一个题目，它查资料，交回一份带出处的文档。

### 以后

远程访问和手机端、给别人用的版本。等 P1–P5 自用稳定后再定。

## 待定事项

需要你定，括号里是我的建议。

1. **omp 配置是否归 Lila 单独管**（建议：是。理由见 `architecture.md` §6。）
2. **邮件和日历用哪家**：Gmail 和 Google 日历、Outlook、还是别的？这决定 P4 选哪个 MCP server。
3. **旧的 Claude Code、Codex 会话**：现在是保留对话、不能继续。（建议：P2 里直接从库里清掉，代码少一个分支。）
4. **命令行保留多少**：现在窗口能做的命令行都能做。（建议：保留，测试和排错都靠它；不再为它加新功能以外的打磨。）

## 做事的方式

- 编码交给 sub-agent（Sonnet 5.5，努力程度 high）；主会话拆任务、定取舍、验收、汇报。
- 验收：重跑编译、测试、clippy；界面改动看截图；每个阶段至少用真 omp 走一遍完成标志里的那件事。
- 真实模型请求按次数限着用，能用假 omp 测的不用真的。
- 汇报时分开写「实测过」和「没验证」。
- 提交和推送都等你说。
