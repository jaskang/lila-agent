# 第一版任务单

目标：在 Mac mini 上用 Lila 完成一次真实的编程任务。架构见 [architecture.md](architecture.md)。

按顺序做，每项做完能单独验证。

## 下一个任务

### 1. 实测 omp RPC

写一个独立脚本，不进正式代码：

- 以 `--mode rpc-ui` 启动 omp 子进程，发一条消息，打印收到的全部事件。
- 触发一次需要审批的工具调用，确认审批请求的格式和回传方式。
- 分别用 Claude 订阅和 ChatGPT 订阅的模型各跑一轮，确认能用、额度扣在订阅上。
- 确认会话恢复、列出可用模型、中断运行各自用哪条 RPC 命令。

产出：一份 omp RPC 事件和命令的笔记（`docs/omp-rpc.md`），作为适配层的依据。如果订阅登录不可用，停下来重新讨论运行时。

## 之后的任务

### 2. 搭仓库骨架

pnpm workspace，三个包：`packages/protocol`、`packages/core`、`apps/desktop`。Electron 窗口能打开，shadcn/ui（Base UI）初始化完成，lint、类型检查、测试命令可用。

### 3. 事件协议

在 `protocol` 里用 Zod 定义 Lila 事件和命令：会话创建、用户消息、助手文本增量、工具调用开始和结束、审批请求和答复、运行结束、出错。每个事件带会话 ID 和序号。

### 4. core：会话与 omp 适配

- 用 drizzle 建表：项目、会话、事件、待审批项。
- 启动和看护 omp 子进程，把 RPC 消息翻译成 Lila 事件并落库。
- 提供订阅接口：从指定序号开始补发并持续推送。
- 测试用录制的 omp 输出回放，不依赖真实模型。

### 5. 桌面界面：会话

- 主进程把 `core` 通过 IPC 暴露给窗口。
- 用 Message Scroller、Message、Bubble、Trace、Code Block 拼出会话界面，流式显示文本、工具输出和 diff。
- 输入框发送消息，可以中断运行。

### 6. 审批

审批请求在界面上显示为待处理项（Questionnaire），用户选择后回传。应用未在前台时发系统通知。

### 7. 项目与模型选择

侧边栏列出项目和会话，可以添加本地目录为项目、新建会话、恢复旧会话。按会话选择模型，模型列表来自 omp。

### 8. 常驻与恢复

关窗口后应用留在菜单栏，任务继续。重新打开窗口从事件日志恢复。应用重启后，未完成的运行标记为中断，可以从已保存的会话继续。

### 9. 用它干一件真事

用 Lila 给 Lila 自己做一个小改动，记录不顺手的地方，决定下一步。
